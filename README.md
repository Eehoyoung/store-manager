# 매장 매니저 (Store Manager)

배달앱·네이버 플레이스 리뷰에 **사장님 말투로 답글을 써 주는** B2B SaaS.
프랜차이즈 가맹점 대상, 매장 단위 월 30,000원(VAT 별도).

> 리뷰 **답글**만 생성합니다. 리뷰 본문을 만드는 코드는 이 저장소에 존재하지 않으며,
> 앞으로도 만들지 않습니다. 리뷰 조작은 표시광고법·전자상거래법 위반입니다.

---

## 무엇을 푸는가

사장님에게 리뷰 답글은 *해야 하는 걸 알지만 계속 밀리는 일*입니다. 하루 10건이 쌓이면
손이 안 가고, 손이 안 가면 별점 1점짜리가 답글 없이 그대로 노출됩니다.

이 서비스는 두 가지를 동시에 노립니다.

| | |
|---|---|
| **사장님에게는 간편을** | 대부분의 리뷰는 손대지 않아도 답글이 나간다. 사람이 봐야 하는 것만 올라온다 |
| **손님에게는 관리받는 기분을** | "소중한 의견 감사합니다" 가 아니라, 내가 쓴 말에 대한 답이 온다 |

두 목표는 자주 충돌합니다. 전부 자동으로 보내면 위험한 리뷰에 기계 답글이 나가고,
전부 사람이 보면 자동화의 의미가 없습니다. 이 저장소의 설계 대부분은 **그 경계를 어디에
그을 것인가**에 대한 답입니다.

## 두 개의 채널, 완전히 다른 경로

### 배달 3사 — 서버가 끝까지 처리한다

DataAPI(기웅정보통신)가 리뷰 조회와 댓글 등록을 모두 제공하므로 **24시간 무인 동작**합니다.
매장 PC 에 설치하는 것은 없습니다.

> **DataAPI 는 스크래핑입니다.** 업체도 플랫폼을 스크래핑해 데이터를 가져옵니다.
> 배달앱 3사와의 공식 제휴나 개방 API 가 아닙니다. 계정 위험은 0 이 아니며,
> 0 이라고 표현하지 않습니다. 조회는 하루 1회, 답글은 리뷰 1건에 1개 — 사람과 같은 빈도로 둡니다.

### 네이버 플레이스 — 서버는 손대지 않는다

네이버에는 공식 API 가 없습니다. 그래서 접근 방식이 근본적으로 다릅니다.

```
확장이 브라우저 안에서 리뷰를 읽고 → 마스킹 → 서버로 전송
서버가 답글 초안을 만들어 돌려주고 → 확장이 입력창에 넣는다
게시는 사장님이 직접 누른다
```

**확장은 어떤 경우에도 게시하지 않습니다.** 게시 감지는 `if (!event.isTrusted) return;`
하나로만 합니다 — 스크립트가 만든 이벤트는 `isTrusted` 가 항상 `false` 이고 위조할 수 없습니다.
`.click()`·`.submit()`·`dispatchEvent(new MouseEvent/KeyboardEvent)` 는 편의성을 명분으로도
도입하지 않으며, **소스 전체를 스캔해 이 API 를 찾는 테스트**가 있습니다.

네이버 리뷰 원문은 서버에 저장하지 않습니다. 스키마로 강제합니다 —
`naver_review_event` 테이블에 **리뷰 본문 컬럼이 아예 없습니다.** 없는 컬럼에는 실수로도
저장되지 않습니다. 보관하는 것은 `SHA-256` 해시와 우리가 생성한 답글뿐입니다.

## AI 파이프라인

```
리뷰 수집
   │
   ▼
① 분류   category(7) · tone(3) · issue/praised tags · risk_level(0~3) · risk_reasons(11)
   │      claude-haiku-4-5, 구조화 출력, 시스템 프롬프트 캐시
   ▼
② 결정론 룰   키워드·정규식·자모 매칭으로 risk_level 을 승격한다 (내리지 않는다)
   │
   ▼
③ 티어 라우팅   난이도로 가른다 — 카테고리가 아니다
   │      T0 룰 템플릿 / T1 haiku / T2 sonnet / T3 opus
   ▼
④ 생성   말투 · 상황 지침 · 매장 사실 · few-shot 을 조립해 답글 초안
   │
   ▼
⑤ 가드레일 G1~G9   길이 · 금칙어 · 금전 약속 · 개인정보 · 경쟁사 · 인용 · 중복 · 위험도 · 인젝션
   │
   ▼
⑥ 게시   risk 0~1 자동 · risk 2 예약 후 알림 · risk 3 사람 검수
```

### ★ 모델을 믿지 않는 것이 설계의 전제입니다

분류는 LLM 이 하지만, **안전은 결정론 룰이 지킵니다.** 실측에서 모델은
`"고소할 거야 각오해라"` 를 risk 1 로 분류했습니다. 그 룰이 없으면 그 리뷰가 자동 게시됩니다.

그래서 층이 둘입니다.

```
1층  LLM 분류기    맥락을 읽는다. 표기가 흔들려도 뜻으로 읽는다
2층  결정론 룰     위생·이물질·식중독·법적·협박 등을 **승격만** 한다
```

두 층은 서로를 받칩니다. 실측(2026-09-20)에서 `"써근 냄새가 나써요"` 를 모델은 risk 1 로
봤고 룰이 risk 3 으로 올렸습니다. 반대로 `"구데기"`·`"곰팽이"` 같은 모음 혼동은 룰이
놓치고 모델이 받았습니다.

### 표기 흔들림

손님은 휴대폰으로 급히 씁니다. 맞춤법 그대로 오는 리뷰가 오히려 드뭅니다.

```
이물질이 → 이물찌리      썩은 → 써근      위생 → 위ㅅㅐㅇ      식중독 → 식중똑
```

정확 문자열 매칭만으로는 **현실적인 표기 18건 중 9건이 등급을 잃었습니다.** 원인은
규칙적이었습니다 — 받침으로 끝나는 키워드 뒤에 모음 조사가 붙으면 연음 표기로 키워드가
깨집니다. 음절 경계를 지우고 자모로 펴면(묵음 초성 `ㅇ` 제거 + 된소리 정규화) 세 유형이
한 번에 풀립니다.

자모로 펴면 **음절 경계와 단어 경계가 함께 사라진다**는 것이 이 방식의 위험입니다.
`담배 ⊂ 담백`, `고발 ⊂ "보고 발견"`. 전자는 *매치 직후가 종성이면 거부*로, 후자는
*공백을 경계 표식으로 보존*해 막았습니다.

### 매장 사실 (store_fact)

`[절대 규칙] 8번`("확인·확정하지 않은 조치를 약속하지 마라") 때문에 주차·대기시간·좌석·
소음·접근성 지침이 전부 *"확정하지 않은 ~를 약속하지 마라"* 로 끝납니다. 그 결과 방문
리뷰의 절반이 `"확인해 보겠습니다"` 한 줄로 수렴했습니다.

**해법은 규칙을 푸는 것이 아니라 사실의 출처를 만드는 것이었습니다.** 사장님이 온보딩에서
확정 입력한 것은 지어낸 게 아니라 받아 적은 것이므로, 답글에 인용해도 8번을 어기지 않습니다.

```
사장님 입력   주차: "건물 뒤 5대, 만차 시 옆 공영주차장 도보 1분"

답글 (전)     "주차 안내를 다시 점검해 보겠습니다"
답글 (후)     "세 바퀴나 도셨다니 불편하셨겠어요. 만차일 땐 옆 공영주차장이
              도보 1분이라 그쪽이 편하실 거예요"
```

실측에서 이 기능이 **부수 효과로 더 큰 문제를 막았습니다** — 매장 사실이 없을 때 모델이
`"큰길에서 오실 땐 편의점 골목으로"` 처럼 **존재하지 않는 사실을 지어내고 있었습니다.**

## 안전 설계

### 자동 게시의 3중 방어선

```
DraftService.tryAutoApprove   →   PublishScheduler   →   worker publish.is_risk_blocked
       생성·예약 시점                게시 직전 재검증          워커 최종 재검증
```

셋 중 하나라도 제거하지 않습니다. 스케줄러는 **분석 기록이 없으면 게시하지 않습니다**
(위험도 미상 = 차단). 워커는 `riskLevel` 이 정수가 아니면 승인 여부와 무관하게 막습니다.

### 위험 등급

| | 내용 | 처리 |
|---|---|---|
| **0~1** | 일반 칭찬·불만 | 자동 생성 → 지연 후 게시 |
| **2** | 화·분노가 드러난 리뷰 | 자동 예약 + **게시 전 알림톡** → 사장님이 철회·수정 가능 |
| **3** | 위생·이물질·식중독·법적조치·언론·협박·리뷰거래·원산지·청소년주류·**환불 요구**·**반복 불만** | 자동 게시 금지, 사람 검수 |

risk 3 이어도 **초안은 만듭니다.** "자동 게시 금지" 가 "생성 금지" 는 아닙니다 —
사람이 사유를 읽고 판단하는 것이 곧 검수이고, 빈 화면을 주면 사장님만 곤란해집니다.

### 절대 하지 않는 것

- 리뷰 본문 생성
- 답글에 금전적 보상 약속 (환불·무료·쿠폰·할인 — 사장님이 직접 입력한 경우만 허용)
- 자격증명 평문 저장·로깅·전송 (KMS 봉투암호화만)
- 네이버 자격증명·쿠키·세션 저장
- 확장에서의 자동 게시
- 영업자료에 "공식 API 연동" · "계정 정지 위험 없음" 표기

### 개인정보

리뷰 작성자 정보는 저장 전 가명처리합니다. 배민은 닉네임이 마스킹되지 않은 원문으로
오기 때문에 특히 그렇습니다(쿠팡이츠·요기요는 이미 `김**` 형태). 네이버는 브라우저에서
1차 마스킹하고 서버에서 `PersonalIdentifierMasker` 로 2차 마스킹합니다 —
**한쪽이 있다고 다른 쪽을 빼지 않습니다.**

## 원가 구조

원가가 사업 모델 그 자체입니다. 전량 고성능 모델은 적자입니다.

| 티어 | 조건 | 모델 | 원가/건 |
|------|------|------|--------:|
| T0 | 무텍스트·NOISE | 룰 템플릿 | 2.14원 |
| T1 | 나머지 전부 | `claude-haiku-4-5` | 4.56원 |
| T2 | risk 2 · 이슈태그 3개↑ · COMPLAINT+별점≤2 | `claude-sonnet-5` | 6.26원 |
| T3 | risk≥3 · ABUSIVE | `claude-opus-5` | 14.22원 |

**카테고리가 아니라 난이도로 라우팅합니다.** "너무 짜서 먹기 힘들었습니다" 에 사과 답글
하나 쓰는 데 상위 모델이 필요하지 않습니다. 이 변경만으로 평균 원가가 23% 내려갔습니다.

시스템 프롬프트는 캐시 임계(4,096토큰)를 넘겨 설계했습니다 — 캐시 적중 시 입력 단가가
1/10 입니다. 실측 캐시 적중률 98.7%.

## 품질 측정

프롬프트 변경은 **합격선을 먼저 적고** 측정합니다. 실행 후에 기준을 정하지 않습니다.

```
ai-python/goldenset/     564건 라벨 코퍼스 + 고위험 강화셋 50건
ai-python/eval.py        평가 하네스 — 행별 예측을 파일로 남긴다
```

| 게이트 | 기준 | 최근 실측 |
|---|---|---|
| 카테고리 정확도 | ≥ 90% | 93.1% |
| ABUSIVE 재현율 | ≥ 95% | 100% |
| risk≥2 재현율 | ≥ 95% | 100% |
| 자동게시 차단 누락 | 0건 | 0건 |

> **골든셋 평가는 기본 꺼져 있습니다.** 1회 실행에 실측 약 1,900원이라, 매장이 몇 개 없는
> 단계에서는 측정비가 매출보다 큽니다. `GOLDENSET_EVAL_ENABLED=true` 로 **사람이 직접**
> 켜야 돌고, 가입 매장 30개 미만이면 켜도 실행하지 않습니다.
>
> **안전은 골든셋이 아니라 무료 유닛테스트가 지킵니다.** `tests/test_risk_rule.py` 가
> 위험 키워드 전종과 오탐 케이스를 함께 검증합니다(비용 0, 0.1초).

### 룰을 넓힐 때의 원칙

> **골든셋에 없다고 안 나오는 게 아닙니다.**

`벌레 한 마리 없이 깔끔했어요` · `불닭 매워요 각오해야 됩니다` · `맛있어서 소문 다 냈어요` ·
`위생장갑이 없어서 손으로 뜯었네요` — 전부 칭찬인데 룰에 걸렸던 실제 문장입니다.
564건 코퍼스에는 하나도 없었습니다. 룰을 넓힐 때는 **관용구를 따로 확인**하고,
오탐이 나오면 키워드를 *지우는* 게 아니라 *좁힙니다*.

## 개발

### 사전 요구사항

- Docker Desktop
- 호스트에서 모듈을 직접 실행하는 경우에만 JDK 17 · Node 22 · Python 3.12+

### 실행

```bash
cp .env.example .env
# .env 에 JWT_SECRET, CREDENTIAL_MASTER_KEY 등을 채운다

docker compose up -d --build

# 웹        http://localhost:15173
# API 상태   http://localhost:18080/actuator/health
```

인프라만 띄우고 모듈은 호스트에서 돌리려면:

```bash
docker compose up -d postgres redis

cd api-spring && ./gradlew bootRun          # 8080
cd ai-python  && uvicorn main:app --reload --port 8001
cd worker     && celery -A tasks worker -l info
cd web        && npm run dev                 # 5173
```

### 포트

호스트의 5432/6379 는 다른 프로젝트가 점유 중이라 다르게 매핑합니다.
**컨테이너 내부 포트는 표준값 그대로**이므로, 서비스 간 URL 에 호스트 포트를 적지 마세요.

| 서비스 | 컨테이너 | 호스트(docker compose) | 호스트 직접 실행 |
|--------|---------:|----------------------:|----------------:|
| Postgres | 5432 | **5433** | — |
| Redis | 6379 | **6380** | — |
| Spring | 8080 | **18080** | 8080 |
| AI Service | 8001 | **18001** | 8001 |
| Web | 5173 | **15173** | 5173 |
| Worker | — | 없음 | — |

`STORE_MANAGER_API_PORT` · `_AI_PORT` · `_WEB_PORT` 로 덮어쓸 수 있습니다.

`store.activated_at IS NULL` 매장은 수집·게시에서 전량 스킵됩니다(전자계약 게이트).
로컬에서 수집을 확인하려면 이 값을 수동으로 세팅해야 합니다.

## 개발 중 주의

- **실매장 계정으로 테스트하지 않습니다.** 테스트 매장 1곳으로만 제한합니다.
- **댓글 등록은 되돌릴 수 없습니다**(수정 API 스펙 미수령). `DATAAPI_WRITE_ENABLED=false`
  가 기본값입니다.
- **DataAPI 를 실제 호출하는 테스트는 CI 에서 금지합니다.** 호출당 과금되고 실매장
  데이터가 걸립니다. 픽스처 기반 목(mock)만 사용합니다.
- **성공 판정은 `data.RESULT == "SUCCESS"` 이면서 `data.ECODE` 가 비어 있을 때만 합니다.**
  DataAPI 는 실패해도 HTTP 200 / `result:"SUCCESS"` 를 반환합니다. 최상위 `result` 로
  판정하면 모든 실패가 성공 처리됩니다.
- 알림톡은 기본 비활성입니다. 휴대폰 소유 인증이 붙기 전에 켜면 그 사이의 고위험 알림이
  **영구 소실**됩니다(유니크 제약이 재발행을 삼킵니다).
